# OpenVLCLIP v0.8.1 validation record

## Status

All three required post-PR #58 SigLIP 2 CPU FP32 official-path checks passed.
This satisfies the numerical parity gate for the v0.8.1 version bump; package
build and existing distribution checks are summarized below.

## Environment and method

- Run date: 2026-11-01 JST.
- Source `HEAD` at test time: `e9be0b87cb26326a00d0222bb0274960575a064d`.
  The SigLIP 2 backend and parity test were unchanged from this commit.
- OS: Windows 11, build 10.0.26300, x86-64; 28 logical processors.
- Python 3.12.10; uv 0.13.1; PyTorch 2.14.1+cpu; Transformers 5.20.1.
- Device and dtype: CPU, FP32 only. CUDA was unavailable and was not tested.
- Each pytest invocation ran in a fresh process. The official
  `AutoModel`/`AutoProcessor` reference and OpenVLCLIP wrapper independently
  loaded the same pinned checkpoint revision.
- Inputs: two synthetic RGB images (320x192, RGB `(210, 30, 40)`; and
  192x320, RGB `(20, 50, 210)`) and the texts `"a red object"` and
  `"a blue object"`.
- The official text processor used fixed 64-token padding and truncation.
  Its output contained no `attention_mask`; the OpenVLCLIP call used the
  corrected no-mask path from PR #58.
- Preprocessed image tensors and token IDs were compared exactly
  (`rtol=0`, `atol=0`). Raw and normalized image/text embeddings and
  bidirectional logits were compared using the existing FP32 tolerance
  (`rtol=1e-5`, `atol=1e-5`). The test also built and queried a two-image
  search index.
- No `integration` extra was installed or requested.

For each model, the existing test asserted both `logits_per_image` and
`logits_per_text`; its JSON output reports the maximum absolute error for the
image-direction logits. Both directions passed the stated tolerance. The
processor tensors and token IDs matched exactly, and the two-image index

Each command below was run separately with
`OPENCLIP_GEMMA_RUN_INTEGRATION=1` in PowerShell:

```powershell
$env:OPENCLIP_GEMMA_RUN_INTEGRATION = "1"; uv run --locked pytest -q -s tests/integration/test_siglip2_official_parity.py -k "cpu and fp32 and siglip2-base-384"

```

Transformers emitted non-fatal configuration warnings that `bos_token_id`
49406 and `eos_token_id` 49407 were outside the reported vocabulary range
0–31999. All three tests completed successfully with no assertion, network,
or resource failures.
